# UUD source and runtime audit

Updated 2026-10-11. UUD recommendations and the rebuilt high-res packs are published after source, renderer and gameplay acceptance. Final rebuilt-pack combinations and fresh popup downloads now pass; earlier checkpoints below retain the investigation history

## Reproduce source checks

```powershell
python game_data/mods/xfing/audit_texture_conversion.py --output android/temp/uud-source-audit.json
pwsh -NoProfile -File game_data/mods/xfing/verify-xfing-minimal-dxa.ps1
```

The Python audit requires Pillow and independently decodes source PIG pixels, including RLE, palettes, transparency and masks. It compares decoded images with the actual DXA contents and checks replacement names against the installed PIG. The JSON output preserves bytes and modification time when unchanged. Archive validation alone does not establish runtime use

The independent audit now verifies 121 D1 images/masks and 1118 D2 images/masks across all seven palettes, with no pixel or runtime-name mismatches. Evidence: `android/temp/uud-source-audit-seven-palettes.json`. This establishes conversion fidelity, not correct runtime lookup or gameplay. The older archive verifier passed even when the seventh palette was missing

The D2 converter previously reused an extracted HAM if one already existed, allowing changes in the source DXA to be silently ignored. It now refreshes that source on every conversion. Optional palette metadata also now refers to the actual D2 baseline instead of the unrelated D1 `DESCENT.PIG` in the stock-data directory

Indexed bitmap acceptance: `android/tests/test_android_mod_bitmaps.ps1` passes eight cases per engine, covering 120 D1 and 1111 D2 source replacements, all seven D2 palettes, paging, semantic flag queries, mission POG overrides/unload, malformed overlay atomic rejection and disable restoration. The independent decoder now also compares generated POG data and metadata, not just PNGs. Source-generated fixture expectations use SHA-256 of decoded palette indices

The D1 semantic fixture now passes 17 cases per engine, including indexed source comparison and an actual mission PG1. D1-in-D2 publishes 119 UUD entries when the mission owns the remaining slot. This verifies mission override preservation at generation publication, where mission data is already loaded before the global mod hook. Evidence: `android/temp/uud-d1-indexed-fixture/{d1,d2}.json` and `android/temp/uud-indexed-native-fixture/{d1,d2}.json`

The generated D1 surface patch has 72 replacements across levels 3, 17 and 20. These are necessary because UUD1 repurposes duplicate textures; shipping images alone changes existing level appearances. Author reference: [UUD1TP](https://descentbb.net/viewtopic.php?f=22&p=391643)

UUD2 includes 30 extra bitmap slots per palette, HAM changes for monitor destruction, restored lava/doors and texture properties. Its author explicitly couples the changed PIGs and HAM. The source also includes a seven-level demonstration mission, which should be used for runtime acceptance. Author reference: [UUD2TP](https://www.descentbb.net/viewtopic.php?p=393747)

## Runtime priority, reload and disable acceptance

Launcher combinations now pass all 15 cases in `android/tests/test_uud_mod_combinations.ps1`: baseline, UUD alone, UUD first with high-res/sound/presentation, high-res first with the same combination, and disabled again, each in D1, D2 and D1-in-D2. The test imports through the launcher, starts fresh engine processes, re-enters the mission and verifies actual indexed/metadata application, rendered pack residency, presentation scope and replacement PCM consumed after re-entry. Evidence: `android/temp/uud-combinations/run_bd20c2e1af17468e9143dbbf7c1d0a4d`

In D1 level one, UUD-first produces one UUD image plus fourteen high-res images; high-res-first produces fifteen high-res images and no visible UUD image, while its indexed and semantic patches remain active. Thus an active semantic mod can have zero visible image replacements in a particular scene. UUD-first is the appropriate recommendation when retaining its corrected artwork matters. The mission gameplay section covers the separate D1 surface and D2 extra-texture acceptance

Renderer acceptance: `android/tests/test_android_mod_renderer.ps1` passes eight D1 and seventeen D2 cases (the latter includes native D1-in-D2). It uses actual UUD and high-res archives, engine bitmap loading, GLES uploads, and full framebuffer image/mask hashes. It covers each pack alone, both priorities, mask ownership, indexed fallback, actual mission PG1/POG overrides, and all 35 flagged-but-opaque D2 door frames. Evidence: `android/temp/uud-render-after/{d1,d2}.json`. The separate KTX2 mipmap fixture passes 48 cases per engine. Native builds, APK packaging and both test catalogs pass (`uud-render-*` logs). The separate launcher integration above passes all 15 scenarios

`android/tests/test_android_d1_mod_patches.ps1` passes 17 real-engine cases each in D1 and D2 using native D1 assets. Final indexed fixture rerun also checks palette-dependent RGB refresh and removal of stale virtual bitmap registration after disabling the HAM patch. Both native libraries build without new warnings; the two scoped Kotlin test classes pass (10 tests), as do both automation catalogs and archive verification. Logs use the `android/temp/uud-indexed-` prefix. Complete regeneration preserved both DXAs' bytes and modification times, recorded in `uud-indexed-repeat-evidence.json`.
