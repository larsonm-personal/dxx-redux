# Pumo native weapon-wall contact observation

This developer-only observer records actual local-player weapon-wall contacts that reach the existing effect-blowup gate. It captures primitive contact identity and pre-effect texture metadata, then the gate result. It is null by default, stores at most two contacts, and reports a lower-bound count that saturates at three. Its dedicated `DXX_PUMO_CONTACT_DEVELOPER_PROBE` macro is defined only for the developer headless metadata target. It does not create a production event bus, use recorder mode, or change collisions or trigger dispatch.

The observer is stacked on the native-ray observation draft at `3ddc3713421f6f8ff37beaa1b1b174f0d028dfa8`. The final developer header is SHA-256 `bf9436ebdba23c0be98911cb703d551212de7d1be481f4a60e2158dc6e3b9a59`; the isolated Release executable is SHA-256 `892f3c72d3577606527410167f878554d4bb9ae63d7d52fd9f5361c863967df3`. The build passed 3/3 focused classic tests, 57/57 public EGL checks, and 36/36 private asset-policy checks. An initial macro-isolation concern was caught before test runs and fixed with the dedicated metadata-only macro. Interrupted partial builds were not gameplay failures.

Two paired runs used the same earned warm level-7 checkpoint, fixed aim, and ordinary controls. Both recorded two player-owned laser contacts on the authored switch wall. Both contacts reached the effect-blowup gate, but neither blew up the effect and the switch did not operate. An opt-in post-contact query sampled the captured overlay texture at each actual contact using the same face-zero UV calculation as the effect consumer. At both contacts, the overlay-only transparency result was 1 while the composed-side result was 0. The loaded overlay bitmap was 64 by 64 with flags 9. The source's non-forced XL blowup predicate uses the overlay-only result, so these two sampled pixels reject the effect. This supports a transparent-pixel miss for the fixed aim, not an engine defect.

The pixel action is read-only, limited to two captured contacts, allowed once after contact, and disabled during recording or replay. Its immediate common-state and RNG snapshots matched. All 17 aligned action snapshots, the actual contact events, and the final states after 12 more ordinary frames matched between the control and query runs, including RNG state and call count. Separate negative controls rejected a query before any contact and a repeated query, with no pixel event for the former and one for the latter. Those expected failures test the guards, not gameplay.

The observer sits after some early returns in the weapon-wall consumer, so an empty record would not prove that no collision occurred. The later pixel query uses the captured pre-effect overlay but samples the loaded bitmap afterward; an animated texture could change between contact and query. This case had no animated effect index in the captured metadata. These observations establish neither successful switch activation nor level progression and do not justify a gameplay change.
