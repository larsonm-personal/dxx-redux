# Effect payload inspection

The bounded 15/33, 17/36 and 23/40 inspector now reads particle, lightning,
ambient-sound and empty thruster payloads. It also reads waypoint controllers and
the known no-payload static movement encoding. These remain runtime blockers.
This chunk improves evidence and rejection messages; it does not qualify another
mission or implement effect activation, playback, damage or rendering.

## Reader scope

The source reference is arbruijn/d2x-xl
2576a98b5de310e3ac7c9777df2677d1627b8bae. `tests/reference_effects.cmake`
hash-checks objects/objectio.cpp and include/object.h and extracts the actual
CObject::Read and FixEffectRenderType functions. Storage/engine adapters compile
those unchanged bodies separately from the inspector. This is an isolated reader
comparison, not a reference-engine gameplay run.

- Particle payloads preserve six integers, RGBA/side bytes and versioned type and
  enabled fields. Older accepted profiles use reader defaults type 0/enabled 1
- Lightning preserves five integers, a modern waypoint, six signed shorts,
  versioned width, flags and RGBA. Earlier accepted profiles default the waypoint
  to -1, width to 3 and enabled to 1
- Sound preserves all 40 filename bytes and the raw volume integer. Its display
  name follows the reader's 39-byte terminator/ASCII lowercase behavior when the
  prefix is printable ASCII; other names remain raw bytes. Volume scaling,
  ownership, file resolution and playback are not implemented by this reader
- Raw IDs and render types remain separate from reference-reader identities:
  waypoint controllers become ID 3, particles ID 0 and sounds ID 2. Lightning
  with a mismatched ID has the reader's render correction exposed separately
- Thruster render 8 has no serialized payload. Static movement 2 also consumes
  no payload in the pinned reader, which logs a warning for it. That warning is
  not evidence of supported static-actor behavior
- Unknown movement, control and render layouts still reject with their value,
  object index and byte offset. In-memory-only render enums are not invented as
  on-disk layouts. Other version pairs remain gated

The metadata browser reports actual per-source effect counts as unsupported. A
source without positive effect records retains the prior unknown category;
absence of this evidence does not establish general effect support.

## Controlled verification

The asset-free `xl_effect_payloads` test passes 75 profiles and 1,980 payload or
controller truncations. It covers all three accepted version pairs, ordinary and
mismatched identities, waypoint/static combinations, empty/embedded-NUL/long/
non-ASCII sound names and unknown layout rejection. All remain blocked by the
gameplay preparation path. `xl_effect_decode_reference` compares every object end,
identity and effect field/default against the extracted reader, including sound
name termination. It passes on MSVC and on Linux GCC with warnings as errors. The
reference's float volume conversion is intentionally excluded: its adapter checks
the serialized integer and cursor, not volume arithmetic.

`xl_effect_inspection_gate` uses the actual engine loader with an owned synthetic
sound level beside unchanged Neptune and a stock level. Rejection must identify
effect_sounds, leave the running geometry/player/source state intact and permit
a supported reload. It never translates or starts the effect fixture.

The normal Android APK and instrumentation APK build successfully. The extended
`test_xl_feature_browser.ps1 -EffectFixture <device-path>` check passes using
e23r13p0.rl2 generated by `xl_inventory_test --effect-fixtures <directory>`.
It calls production JNI inspection and opens the production dialog, checking the
23/40 format, sound count, blocked status and unsupported explanation. The
captured dialog shows those facts. Only emulator-5554 was used; the two owned
staging files were removed afterward. No mission import or 3D traversal occurs.

All 18 focused native checks pass after correcting the stock control to use an
ordinary descriptor. The other 17 passed in the first sweep. All 12 private
policy checks, both automation catalogs and scoped mixed formatting pass. Both
candidate reports regenerate with identical bytes and modification times.
