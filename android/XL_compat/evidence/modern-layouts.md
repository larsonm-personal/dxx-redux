# Version-25/27 inspection and Pumo requirements

The bounded reader now inspects 25/40 and 27/40 files. The standalone inspector
streams its HOG input and reads one bounded level payload at a time; it can
inspect the unchanged 196505200-byte Pumo HOG. Subsequent
[canonical runtime controls](runtime-layouts.md) qualify bounded translation;
independent feature gates still reject every Pumo level.
These results establish the serialized requirements, not playable missions.

The new layouts have signed 16-bit producer/value fields, four explicit corner
slots per side (including untextured portals), and deleted vertex sentinels
0xfff8..0xffff. Missing trailing corners use 255. Textured triangular sides still
store all four UVLs. Version 27 inserts four RGB/distance records before the
level name; each distance byte represents 20 units. The inventory preserves raw
slots and compares their global vertex identities to the reference's compacted
representation. It rejects invalid slots, references to deleted vertices and
non-trailing missing corners. Noncanonical or shortened sides remain explicit
runtime blockers, including source-degenerate zero-, one- and two-corner sides.

The reference adapter uses the real signed-byte contract. Its negative signed
UV shifts are replaced with equivalent bounded multiplication for defined C++17
arithmetic. Storage adapters and the four-record fog loop are separate from the
extracted reader logic. No runtime geometry or renderer is simulated by this test.

## Correction to earlier light-index source evidence

The older light-index oracle incorrectly exposed CFile::ReadByte as unsigned.
The pinned implementation returns int8_t. The corrected adapter now hashes both
the declaration and implementation and explicitly measures the discrepancy.
Of 131072 legacy/packed bit patterns, 65536 differ from unsigned encoded counts.
For packed records, low-byte sign extension adds 32 to certain counts, wrapping
at 8192; legacy count bytes above 127 also sign-extend into the 13-bit field.

Redux continues to decode the documented unsigned encoded count. This is an
intentional correction to a reference bug, not bit parity with that reader.
The source oracle replaces only negative left shift with multiplication and
preserves the anomalous signed result for comparison. On Pumo's 1156 indices,
553 source counts differ and six source ranges overrun the declared delta table.
All authored unsigned ranges are valid. The existing Apocalyptic Factor audit
still has one valid and fourteen rejected levels; its corrected source run
records 28 count differences and 332 source range overruns. No production decoder
behavior was changed by correcting the oracle.

## Remaining Pumo dependencies

The new inventory removes noncanonical geometry from Pumo's known requirements.
The subsequent runtime tranche removes the canonical layout gate while retaining
independent feature gates.
Every level requires sound/effect objects; thirteen have particles and three
have lightning. Twelve contain unsupported property combinations. The campaign
also uses skyboxes/outdoor regions, effect targets, message/sound/countdown and
other extended actions, wall variants, equipment and additional object types.
The refreshed inventory no longer reports the old 23/40-only equipment profile
or incorrect authored-index assignment restrictions. Eleven levels require
version-27 authored fog application.
Custom HXM, POG, WAV, MSG, SND and INI resources need actual ownership, decoding,
application and transition tests; their presence is not implementation evidence.

Canonical 25/27 runtime translation and persistence now have
[separate controls](runtime-layouts.md). Next implement the authored
visibility/effect/event/resource dependencies in that order where they interact.
Original campaigns remain human playtesting work. No autonomous
3D navigation or mission-name exceptions are involved.
