## What would justify full support

Keep a row for every original distribution and signed ordinal. Record the selected bytes, required addons, modes and transitions alongside three independently observable results: what the pinned original can do with that installation, what Redux can start, and what a player can finish. Preserve unavailable packages, inconclusive reference runs and unplayed levels in the published totals. A second installation with authentic assets from the private repository gets its own result. Equal mine bytes can share a gameplay recording only after verifying that the effective mission resources, rules and destination also match.

Use ordinary inputs to record paths from the actual start to each required objective and exit. Verify the destination, retained inventory and persistent world changes, and continue after loading a disk save in a new process. Include secrets, return paths, hubs and finales where the mission defines them. For an arena, use real peers and the authored mode's scoring condition, such as a flag capture and score on both peers. The existing Ahayweh Gate escape and Pumo PMC finale give working examples of earned events. Pumo still needs the intervening routes joined across the 14-level branch. A checkpoint created by a controlled approach remains useful for diagnosis and cannot fill a missing route.

Choose runtime work by which of these routes it blocks and by how many other missions use the same behavior. Compare the first differing gameplay event with the original. Follow the data through decoding, runtime selection, simulation or drawing, and save/load or network replication where applicable. For example, Pumo's first level runs in the original with high-resolution textures enabled. Its first rejected object effect in Redux uses slot 33 and eleven source frames. The original rendered those eleven frames. That gives the next port an observable result before attempting the route again. Other families already visible across the catalog include packed light indices, texture residency, level layouts and segment functions. Record latent consumers in passing starts too, including reactors, generators and triggers.

Use the fixed eight and 64 for pull-request feedback, the full startup census for regressions, and a rotating set of recorded routes for longer private CI. Retain the last passing ordinary route per engine revision, distribution, mode and platform. Count a connected route as covered only through its last earned event. A campaign needs its reachable endings and branches covered, and an arena needs its supported modes exercised. Report platform gaps explicitly. The next forecast should use the rate of completing routes and the rate at which those routes expose new subsystem work. Startup gains alone cannot supply either rate.
