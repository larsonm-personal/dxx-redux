1. HARQYJIA LEVEL 2 - CONFIRMED MEMORY CORRUPTION, FIXED

The original result changed from ok to timeout. Three repeated runs of the
captured engine reproduced the timeout. Reversing the fireball RNG change did
not repair it.

Phase instrumentation traced the corruption to incidental trigger 49, an
OPEN_WALL trigger with 10 links. Existing transitions exhausted the 10-slot
CloakingWalls array. start_wall_cloak wrote d->time = 0 to slot 10 before its
capacity check. At GameTime64 10527266, three overflow writes for walls 56, 58
and 60 landed at exactly the address of ActiveDoors[1].front_wallnum[0]. The
next frame retired that corrupted entry while wall 140 remained opening.
This blocked the route indefinitely. The same ordering defect also existed
in start_wall_decloak.

Fix: move allocation and time initialization after the existing capacity check
in both functions. Existing full-capacity fallback behavior is preserved.
D1 has no corresponding wall-cloaking transition implementation to change.

The new upstream compatibility integration test fills the actual transition
queue while two ordinary doors are opening, exercises both overflow paths,
checks that both animation arrays remain intact, and verifies the ordinary
doors finish opening. Linking the NEW test with the ORIGINAL wall.c fails
the exact queue-preservation assertion. Linking the fixed code passes.

The normal producer regenerated the entire Harqyjia mission using the fixed
CMake-built engine with Repeat=3. All five level results were byte-identical
across their three runs. Level 2 is now ok, 10703 frames. Levels 1, 3, 4 and
secret -1 are unchanged, including the pre-existing level 3 timeout.
Only game_data/mission_files/d2xxl_downloads/harqyjia.simulation.json was
republished during this investigation. Original failure JSON is preserved.

Evidence: phase_trace/runs_4; cloak_negative/test.log; cloak_fix/runs_2;
harqyjia_fixed/summary.json and results; completion_audit.json
