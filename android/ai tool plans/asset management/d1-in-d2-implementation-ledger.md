## Publication and normal level loading

`d1_in_d2_publish_assets` installs the complete prepared base tables and original source IDs. The generation transfers model bytes and the sound arena to existing engine owners and retains ownership of resident bitmap pixels. Registry cleanup retires that generation, including custom replacements, without loading D2 resources. Mutable live animation tables are copied from prepared definitions

The engine changes are bounded integration points:

- `piggy.c`: a generic registry reset and reuse of the existing registry initialization; the close hook releases D1-owned images. Reset invalidates uploaded high-resolution images as well as paging/RLE/merge state
- `gameseq.c`: prepare before `load_level` and skip the D2 robot replacement path for an active native D1 generation
- `gamemine.c`: preserve D1 texture IDs and orientation when the active generation is native D1
- `mission.c`: delegate profile preparation before a HAM reload. This both skips D2 HAM loading for D1 and retires D1 registries before switching to D2
- `bm.c`: use the already imported original D1 exit models rather than truncating/reloading them through the D2 extra-model path

Profile ordering is owned by the facade. A test that included the real mission HAM reload exposed a sound-name hash overflow when cleanup occurred only at level start; moving cleanup before that reload fixed the ordering. Returning to D2 restores its palette/registry and optional replacement models; publishing D1 clears cached D2 replacement models

Native `.pg1`/`.dtx` bitmap replacements resolve against original names or explicit source indices. The existing legacy mapping remains available for legacy callers. Native publication supplies all base sounds; the custom loader no longer reimports them. For the plain SDL backend, publication converts the sample bank to the configured device rate so original 11 kHz sounds keep their duration; the mixer can consume their original frequency directly

Original texture definitions install `destroyed = -1`. The temporary D1 light guards in `collide.c` and `wall.c` have been removed, with direct-hit, forced-hit, nearby-blast and monitor tests passing through the normal engine handlers. The legacy destroyed-light palette conversion is retained

## Presentation ownership, profile switching and original menus

The presentation owner now coordinates text and font activation with asset publication. It retains D1 and D2 text banks across profile switches so an existing menu's string pointers remain valid; shutdown restores the engine-owned D2 pointers before their ordinary cleanup. When fonts are installed, activation releases cached menu backgrounds and reloads the selected profile's font configuration. Clearing the old font configuration prevents retained D2 high-resolution entries from appearing in D1

Base presentation archives are mounted under separate owned prefixes. Resource selection distinguishes base archives from mission/loose overrides: same-named base resources resolve from the selected game, while an override at the normal search-path precedence remains effective. Missing D1 resources cannot silently resolve from a mounted D2 base archive. The owner releases its archive handles during text shutdown, after fonts have closed

Original menu palette and fullscreen/stars/frame background choices now belong to the presentation owner. The existing menu macros delegate by resource role, retaining their D2 defaults; no menu event handler gained D1 selection logic. D1 chooses its native `menuh.pcx` convention when that optional image exists, otherwise its original low-resolution artwork. Shared palette loading resolves the physical source separately from the short logical palette cache key
