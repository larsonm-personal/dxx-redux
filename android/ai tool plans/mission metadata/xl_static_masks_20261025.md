# Mission-owned static binary texture coverage

This slice starts at PR128 commit 642d77b4af36475c3f6701ed5778014ba823936e on a new xl-static-masks branch. It leaves xl-next-resource and xl_more unchanged. Animation and partial-alpha blending remain separate later slices; no whole mission is admitted here.

## Evidence and scope

Use the [31-file measured manifest](xl_texture_followon_evidence_20261025.json), pinned to test-assets d9fbeaf6eb059fd4504308bfd6364734775b7cba and levelpack SHA256 b4b519dc5755b795fd49cc3786a0421b96cd099dcc8f002925ddfd7c038b2719. BoilingPoint fan03.tga and misc075.tga are each 263205 bytes, 256x256, Pillow-normalized alpha255; see the decoder correction below. Their 28375 and 21878 purple-key pixels respectively encode super-holes. Full source hashes are retained in that manifest. The initial Pillow survey normalized TGA extension alpha type0 and therefore did not expose stored alpha. The actual engine decoder and pinned XL raw reader disagree with that normalization: misc075 has 21878 alpha0 super-key pixels, 26379 additional ordinary alpha0 pixels, and 17279 opaque pixels. It is the selected binary witness. Fan03 has 28375 alpha0 keys, 22811 ordinary alpha0 pixels, 14349 opaque pixels and ONE non-key alpha104 pixel (stored pixel47303, RGB124/93/132). Fan03 remains rejected until partial-alpha qualification. Synthetic cutouts remain useful independent controls. No source bytes are rewritten or normalized to force admission.

A bounded read of the original retail HAM/PIG tables maps texture335 to bitmap1562 misc075 and texture336 to bitmap1563 fan03. All six retail PIGs carry flags11 (transparent, super-transparent, RLE) for both. The BoilingPoint HOG contains no POG overrides. A read-only geometry probe following pinned XL CSegment::Read found four matching sides each in watrwrks.rl2, control2.rl2 and control.rl2; none in the other four levels. Waterworks uses both as overlays. The control levels additionally use misc075 as a base. The [material manifest](xl_static_masks_materials_20261025.json) records level hashes and exact sides, not mission bytes. This is bounded geometry evidence, not general v23 reader or runtime support; the production inventory still rejects these levels.

## Implementation contract

Derive color and semantic mask from the same owner-validated TGA allocation before resizing. Ordinary alpha0 removes only the overlay contribution; a purple super-hole removes combined wall coverage when used as overlay. When used as base or standalone artwork, a key removes that source's coverage; an opaque overlay can cover a base hole. Never mutate gameplay bitmap flags. Carry source classification on the renderer texture and clear it with the existing texture lifetime.

Keep POG/custom priority, owner/case validation, foreign-source rejection, global-index exclusion, D1 and D1-in-D2 behavior unchanged. Reject partial alpha, tall strips and animation names. Binary materials require power-of-two source and fitted dimensions in this first profile. Gate combined super-holes on the merged renderer; no GLES1/two-pass equivalence claim.

Reuse the engine upload and tex2/tex2m shaders. Source-specific binary thresholds leave legacy shader behavior unchanged. Build color and mask mip coverage together without searching averaged RGB for keys. Conservative minimum coverage preserves narrow holes but can widen subpixel openings; this explicit bounded policy is not a claim of pixel-identical XL filtering. Exclude transparent RGB from color averaging to avoid purple fringes. Keep decoded/color/mask allocations bounded, and fail the complete replacement if either GPU upload fails.

## Single-binary mission isolation

Compiled availability does not activate this new mission-owned D2 texture capability. The selected mission policy starts disabled and is sealed only after successful descriptor parsing and archive selection: an explicit parsed `d2x-name`, or a listed normal/secret extended level resolved from the selected HOG, enables the qualified resource scope. Browser hints, unlisted HOG members and the presence of `mods/...` textures do not enable it. This snapshot is not recomputed during drawing. Native archive identity, Android package ownership/generation and each decoder's capability checks still apply. Unsupported level semantics remain separately rejected. D1 and classic custom missions retain their existing paths in the same XL-enabled binary. The archive getter remains an ownership identity, not an activation flag. Existing imported-D1 scoped WAV and companion-inspection consumers retain their separate contracts; their classic-format Dragon Pit witness must not be disabled by a D2-format texture gate. The texture call site applies the sealed capability before using that identity. A unified policy for classic-format packages carrying XL resource extensions remains a separate architectural task; this texture policy does not claim to solve it.

Preflight failure preserves the prior live mission and its policy. Committed teardown clears both the snapshot and the complete live XL preview state (source, admitted profiles, trigger state, lighting and pending translation); successful reselection and save restoration establish the new identity through the existing mission path. This does not promise mathematical proof of every engine transition. Tests cover the concrete boundaries, and no production default or LAN setting is globally enabled by this change.

The external `-xl-source` translated-level shortcut is compiled only into the explicit native lifecycle test target (`DXX_XL_DEVELOPER_PROBE`). Ordinary XL-enabled Android/desktop targets cannot activate that developer bypass. The lifecycle target retains the useful original-to-translation test, while compiled production object inspection verifies the external-source branch is absent.

Native descriptor coverage now creates a real classic custom HOG with a stock level, an unlisted XL member and a matching synthetic purple-key TGA layout. It verifies classic selection stays disabled, adding the owned XL secret declaration enables mission scope without admitting unsupported secret semantics, and reselection recovers classic policy. Original Observatory selection/stock transitions and malformed-descriptor rollback assert the sealed identity. Original Robotech save restoration asserts resource identity alongside existing state/RNG checks. The controlled GLES fixture also renders the same mounted package first under injected classic identity and then under injected XL identity. That injection remains an explicit limit: it is not a full mission-load GPU integration test.

The native water integration additionally starts from an admitted live water level, commits classic mission selection, and attempts missing and truncated classic level loads. It checks that gameplay and resource identity are already cleared before either failure, then loads stock and recovers the original arena. Preflight rejection that leaves the old mission selected remains transactional.

A preservation check found that gating the shared ownership getter itself suppresses Dragon Pit companions. The pinned original companion-ownership probe reproduced that regression. The correction restores the getter contract and gates only the new D2 texture path. The native original-Dragon probe also asserts that imported-D1 ownership remains available without enabling D2 texture scope. The renderer fixture supplies the same archive identity under both classic and XL policy to verify that ownership alone cannot activate textures.
