## Tappable explanations

Every category and counted feature uses an accessible, at least 48dp row button.
Counts/status stay in the list. A second dialog separates **What XL does** from
**Current Redux support**. Back or **Back to features** dismisses only that dialog;
the underlying feature list and scroll position remain mounted. Long text scrolls.
There are no tap-time network calls, resource loading or gameplay launches.

Explanations live alongside IDs in the native catalog. The JSON model carries
those fields without a second support/status mapping. Older or unknown reports
get an explicit unverified-explanation fallback. Water's short row stays compact;
its longer support note states bounded original Robotech physics/save validation,
logic-only audio checks and unqualified audible/visual parity.

Water source references are arbruijn/d2x-xl at
`2576a98b5de310e3ac7c9777df2677d1627b8bae`: `physics/physics.cpp` fluid time scale,
`physics/collide.cpp` contact/turbulence, `main/segment.cpp` fluid damage,
`objects/updateobject.cpp` submerged/waterfall sound selection, and
`gameio/loadobjects.cpp` default blue water fog. The explanation conditions 75%
motion on enabled fluid physics and normal speed settings; it does not promise
that Redux reproduces XL's rendering. Other categories describe only their
established role, without inventing semantics for uninspected records.

Validation covers native blurb/status serialization, JVM native-field/fallback
handling and actual Compose taps/Back/Close. Instrumentation obtains all native
blurbs through JNI from a synthetic descriptor, then uses explicitly synthetic
counts to exercise row rendering. It checks water/unsupported teleport dialogs,
long text in light/dark themes, unknown/legacy fallback and return to a nonzero
feature-list scroll position. It does not load a mission or qualify gameplay.
