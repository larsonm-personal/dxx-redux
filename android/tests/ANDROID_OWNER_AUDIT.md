# Android owner prerequisite audit

All **198 original non-host master owners** are classified: 95 JSONC, 84 ordinary PowerShell and 19 native-fixture wrappers. Together with the separate 148-owner host audit, this accounts for the original 346 direct master entries. Some original “emulator” entries actually run native host tools or interactive support services; category labels alone are not hardware evidence.

These are source requirements and eligibility decisions, not executed tests. A registry owner is not an individual assertion. Child scripts, explicit game/profile variants, co-op matrices, optional switches and trace records remain separate. The static inventory’s unmapped/support files are not automatically independent runnable suites.

## Useful runnable expansion

- The 95 JSONC owners include 26 shareware-capable owners with 49 explicit public game variants and four already-admitted launcher-only owners. Four further public/generated owners need narrow admission; two need concrete public-package provisioning. The other 57 unchanged fixture contracts pin private base/expansion assets; two are manual.
- Eleven of the 19 native Android wrappers generate all runtime media. They retain **2,204 expected trace records** across both engines, including real GLES and OpenSL checks. Seven other wrappers stage external assets; matcen additionally runs a full retail gameplay phase. See [native audit](ANDROID_NATIVE_FIXTURE_AUDIT.md).
- Eight additional owners are independently source-reviewed as media-free. Five have default-only gates: standalone PCM ring, APK touch-layout codecs, launcher build metadata, emulator xCrash diagnostic and LAN transport retry. Multiplayer recovery, active discovery and selected-emulator recovery are reviewed candidates with explicit provisioning caveats: generated loopback traffic, initialized preferences/host UDP42400/10.0.2.2 reachability, and two isolated idle managed AVDs respectively. Admission and runtime execution remain separate.
- The two co-op readiness owners can use genuine public D1/D2 fixtures but still need fixed routing profiles. The save-compatibility positive-version bug is source-fixed by deriving the production header constant; runtime remains unqualified.
- Public-profile gaps include live controller rebind and runtime texture options, which already use shareware-marked scripts; whole-owner wrappers still need explicit fixture routing. Public matcen is a native host profile despite its original emulator classification.
- Only `test_device_network_campaign` in the PowerShell slice explicitly requires two physical devices and rejects emulator serials. Other networking owners need the appropriate AVD topology, server or permission profile, not a blanket physical-device exclusion.

## Fixture and tool requirements

The detailed [machine-readable audit](android_owner_audit.json) gives every owner’s exact classification, source evidence, declared dependencies and next step where applicable. Standard retail provisioning requires all eleven filename/SHA-256 identities from `helpers/standard_game_data.ps1`; the audit records them explicitly. Mission/mod/disc owners retain their named original packages and child `_deps`. These files are not available from an Android SDK installation.

Native fixture owners require the retained ABI-matched Debug `.cxx` CMake build, both engine libraries and dependency headers, not just an APK. Touch-layout additionally needs matching runtime `classes.jar`, JDK, D8 and the SDK platform JAR. Dual networking requires supported shared-Wi-Fi emulator topology and actual packet assertions. Full demo import is pending seven missing exact originals, detailed in [corpus availability](DEMO_IMPORT_CORPUS_SOURCES.md).

## Coverage boundaries

The sweep can finish all eligible catalog selections across bounded test batches. Setup/build time is separate from the approximately 45-minute execution allocation per lane (up to four parallel lanes); native owner fixture compilation remains inside its existing timeout. A failed/skipped prerequisite stays pending, and eligible does not mean passed. Optional/manual/physical/private-source profiles remain explicit with their concrete blockers, rather than silently counting as covered.
